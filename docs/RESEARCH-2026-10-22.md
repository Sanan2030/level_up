## Important distinctions checked during review

- RFC 9700 requires PKCE for public authorization-code clients and recommends it for confidential clients. The lesson chooses it for both without falsely turning the recommendation into a universal RFC MUST.
- OAuth access tokens need not be JWTs. Refresh tokens belong at the authorization server, not ordinary resource APIs. Refresh grants do not silently expand granted scope.
- Rotation/reuse detection and client single-flight coordination solve different parts of the problem. Logout does not universally invalidate an already issued self-contained access token immediately.
- JWT decoding is not verification, a valid signature is not an audience check, and valid token/scope is not object ownership. A token-controlled JWKS URL is not a trust anchor.
- SameSite is not same-origin. HttpOnly does not eliminate authenticated actions by an XSS payload. CORS is not API authentication and blocked response access does not prove no request was processed.
- HTTP idempotent semantics do not require identical response bytes. Operation-key syntax/expiry/conflict policy are application choices, not invented universal HTTP mandates. Atomicity requires the actual datastore boundary.
- Outbox publishing can duplicate deliveries. The Cosmos DB source's local transaction is restricted to a logical partition; the lesson separately labels relational pseudocode. An HMAC proves protected bytes, not freshness or one-time processing.
- Sagas do not supply global ACID isolation; compensation is a new business action and can fail. CQRS does not imply event sourcing. Domain, deployment and Scrum product boundaries are different decisions.
- The feature-toggle article permits latent unfinished engineering paths; this does not override the Scrum Guide's requirement that an Increment be usable and Done. Disabling a flag does not reverse irreversible business effects.
- The experiment table is synthetic and its segment/aggregate arithmetic was checked. It illustrates a reversal, not a real measured product outcome or a universal statistical stopping rule.
- GOV.UK, Microsoft and the Hodgson article supply explicitly supplementary practices. They neither define Scrum accountabilities nor establish official PSPO coverage.
